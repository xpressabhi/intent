# Intent v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Intent v2 bundle — lean two-part records (`proposal.md` with YAML front matter + `conformance.md`), a verifier with body-only digests and glob-aware declarations, a CI coverage gate, a v1→v2 migrator, and matching docs/tests.

**Architecture:** `change.yaml` disappears; its machine fields become front matter on `proposal.md`, whose body stays the digested, human-authored intent. `scripts/verify-change.sh` is rewritten around a front-matter parser; `scripts/verify-records.sh` gates change ranges; `scripts/migrate-v1.sh` converts existing v1 records; the installer stages a v2 manifest shared with the migrator via `scripts/lib-bundle.sh`.

**Tech Stack:** POSIX `sh` + `awk`; JSON Schema for records; shell test scripts; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-13-intent-v2-design.md`

## Global Constraints

- POSIX `sh` only (`set -eu`, no bashisms); must run on macOS (`shasum -a 256`) and Linux (`sha256sum`).
- Digest = SHA-256 of the body bytes (everything after the front matter) with all CR bytes removed (`tr -d '\r'`); a leading BOM is a failure; front matter is never digested.
- Front matter is the restricted YAML subset in the spec §3.2; anything else is an explicit parse error (never a silent mis-parse).
- Message prefixes: `verify-change: FAIL: `, `verify-change: error: `, `verify-change: WARN: `, `verify-records: `, `migrate-v1: `, `intent install: `.
- Do not modify `protocol/v1.md`, `schemas/v1/`, `conformance/v1/`, `examples/v1/`; v1 content stays readable and is no longer installed.
- Bundle paths are exactly: `protocol/v2.md`, `schemas/v2/{change,config,review}.schema.json`, `scripts/{verify-change.sh,verify-records.sh,migrate-v1.sh,install.sh,lib-bundle.sh}`, `install/manifest.txt`, `install/templates/**`, `conformance/v2/scenarios.md`, `examples/v2/**`.
- No network access from tests; tests write only under `mktemp` directories.
- Conventional commit messages. Work on a branch `intent-v2` (operator may override).

## Review Focus

The spec implies these failure modes; each is pinned by a test in the task that owns the code.

1. Paths containing spaces in git diffs — scope/protected matching must report correctly, not crash or skip (Task 2).
2. CRLF front matter from a Windows-authored file — the `---` delimiters must parse after `\r` strip and the digest must be unchanged (Task 1).
3. `proposal.md` with no front matter, or a body whose first content line is `---` — explicit parse error, never a silent digest of the wrong byte range (Task 1).
4. Declared globs: one matching nothing warns; one matching everything (`src/**`, `**/*`) is allowed and must work — no shell pathname-expansion bug (the regression) (Task 2).
5. `Intent-Skip:` appearing inside ordinary commit text versus a real trailer at line start — only line start counts (Task 4).

## File Structure

- `scripts/verify-change.sh` — v2 record verifier (rewritten across Tasks 1–3).
- `scripts/verify-records.sh` — range coverage gate (Task 4).
- `scripts/install.sh`, `scripts/lib-bundle.sh`, `install/manifest.txt` — installer + shared bundle resolution (Task 5).
- `scripts/migrate-v1.sh` — one-time v1→v2 migrator (Task 6).
- `schemas/v2/*.json`, `protocol/v2.md` — the v2 contract (Task 1).
- `install/templates/**` — v2 guidance, record templates, CI template (Task 5).
- `tests/verify-change.sh`, `tests/verify-records.sh`, `tests/migrate.sh`, `tests/install.sh` — one test file per script.
- `.github/workflows/tests.yml` — runs this repository's tests (Task 1). (The `intent-verify.yml` template for *adopters* lives under `install/templates/`, Task 5.)
- `conformance/v2/scenarios.md`, `README.md`, `docs/install-prompt.md`, `docs/index.html`, `docs/diagrams/*`, `examples/v2/**` (Task 7).
